# Интеграция Spooky Events bot — что сделано и как задеплоить

## Суть

Доступ к @Sp00kyEventsBot продаётся на сайте InsideClient ровно как
существующий тариф «Доступ к боту» (`bot`, 50₽, `js/buy.js`) —
отдельная новая колонка в БД **не понадобилась**: поле `users.bot_access`
уже было задумано именно под это (дашборд уже показывал значение
`@Sp00kyEventsBot`, когда `bot_access = 1`).

Купить/активировать этот тариф можно только с привязанным Telegram —
без этого сайт теперь прямо отказывает с понятным сообщением
(и на кнопке «Купить», и при активации ключа).

Сам Spooky-бот — отдельный процесс на Python, будет отдельным
Railway-сервисом рядом с сайтом. Перед тем как ответить на `/start`
(и вообще на любое действие в личке), он спрашивает у сайта:
`GET /api/internal/spooky-access?chat_id=...` с заголовком
`X-Internal-Secret`. Если доступа нет — присылает сообщение
«нужно купить доступ» со ссылкой на `@InsideClientBot` и не даёт
пройти дальше ни в один хендлер. Весь остальной функционал бота
(2200+ строк логики ивентов) не тронут вообще.

## Что изменено

**Сайт (`server/server.js`):**
- `handleBuy` — для `plan === 'bot'` требует `user.telegram_chat_id`,
  иначе `409` с понятной ошибкой вместо редиректа на FunPay.
- `handleKeyActivate` — та же проверка перед активацией ключа с
  `reward_type = 'bot_access'` (ключ при отказе остаётся неактивированным,
  можно ввести его же после привязки Telegram).
- Новый внутренний роут `GET /api/internal/spooky-access` — сверяет
  `X-Internal-Secret` (`timingSafeEqual`, не обычное сравнение строк),
  ищет юзера по `telegram_chat_id`, отдаёт `{ access: true|false }`.
  Не публичный, не вызывается с фронта.

**Spooky-бот (`main.py`):**
- Новый блок «ДОСТУП» — `check_spooky_access()` (HTTP-запрос на сайт,
  кэш на 60 сек, при недоступности сайта донашивает последний известный
  «да» ещё 10 минут, чтобы платящие не отваливались из-за случайного
  даунтайма) и `access_gate()` — глобальный хендлер `group=-1`,
  регистрируется раньше всех остальных и останавливает обработку
  апдейта (`ApplicationHandlerStop`), если доступа нет.
- Гейтится только личка (`chat.type == "private"`), группы не трогает.

## Переменные окружения

### Сервис сайта (InsideClient) — добавить в Railway Variables

```
SPOOKY_INTERNAL_SECRET=<длинная случайная строка, придумай сама>
```

(остальные переменные сайта не менялись)

### Новый сервис Spooky-бота — все переменные

```
BOT_TOKEN=<токен от @BotFather — ПЕРЕВЫПУСТИ старый, он был в переписке>
API_ID=21717369
API_HASH=b5caf5666662d13269405c7189d44c60
SESSION_STRING=<получить один раз через generate_session.py, см. ниже>

INSIDE_CLIENT_API_URL=https://<домен-сайта-на-railway>
SPOOKY_INTERNAL_SECRET=<та же строка, что на сайте>
INSIDE_CLIENT_BOT_USERNAME=InsideClientBot
```

`SPOOKY_INTERNAL_SECRET` должен быть **одинаковым** на обоих сервисах —
это общий пароль между ними, не показывай его нигде, кроме Railway
Variables.

## Как получить SESSION_STRING (сделать один раз, руками)

Это единственный шаг, который не получится сделать без тебя — нужно
ввести код подтверждения из Telegram, а его вижу только ты.

1. Локально: `pip install telethon`
2. `python generate_session.py` (лежит в архиве Spooky-бота)
3. Введи номер телефона аккаунта, который будет юзерботом, потом код
   из Telegram (и облачный пароль, если включена двухфакторка)
4. Скрипт выведет строку — вставь её как `SESSION_STRING` в Railway

Рекомендация из README самого скрипта: лучше отдельный Telegram-аккаунт,
не основной личный — это будет слать сообщения `@SpookyTimeBot` каждые
~6 секунд круглосуточно, у официальных ботов бывают лимиты на такой
паттерн.

## Деплой

Два отдельных Railway-сервиса из одного проекта (разные рантаймы —
Node и Python, разные зависимости, нет смысла тащить их в один процесс):

1. **Сайт** — как раньше, `railway.json`/`start.sh`, ничего не меняется
   в процессе деплоя, только добавляется `SPOOKY_INTERNAL_SECRET`.
2. **Spooky-бот** — новый сервис, тот же репозиторий или отдельный,
   `Procfile: worker: python run_all.py`, все переменные из списка
   выше. После первого успешного старта в логах будет
   `✅ Userbot (Telethon) авторизован через SESSION_STRING как <имя>`.

Порядок: сначала сайт (там же будет `INSIDE_CLIENT_API_URL`), потом
Spooky-бот — иначе `INSIDE_CLIENT_API_URL` некуда будет указать.

## Не забыть

- Перевыпустить `BOT_TOKEN` через @BotFather — старый был в переписке.
- `SPOOKY_INTERNAL_SECRET` — придумать один раз, вставить в оба сервиса.
- Если `bot_access` уже стоит `1` у кого-то из старых тестов — он
  получит доступ сразу после деплоя, это ожидаемо (флаг переиспользуется).
