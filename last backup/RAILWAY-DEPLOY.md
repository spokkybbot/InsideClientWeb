# Деплой Inside Client на Railway

Коротко: это Node.js-сайт без внешних npm-зависимостей (используется
встроенный `node:sqlite`), который сам раздаёт статику и отвечает на
`/api/*`. Плюс отдельный процесс Telegram-бота (`server/bot.js`).
Обоим нужен доступ к одному файлу SQLite в папке `data/`.

Отвечая сразу на твои вопросы:

- **Volume — нужен, обязательно.** Railway пересоздаёт файловую систему
  контейнера при каждом деплое/рестарте. Без Volume база данных
  (`data/inside-client.sqlite`) будет обнуляться, а все пользователи и
  покупки — пропадать.
- **Variables — нужны, но по минимуму.** `PORT` Railway подставляет сама.
  Тебе вручную нужно задать только переменные для Telegram-бота (см. ниже),
  если он используется.
- Бот я запускаю **вторым процессом внутри того же сервиса** (через
  `start.sh`), а не отдельным сервисом Railway — так они гарантированно
  работают с одним и тем же файлом БД на одном и том же Volume, и не нужно
  возиться с шарингом Volume между двумя сервисами.

## 0. Что лежит в архиве

Структура — без вложенной папки `inside-client/`, всё сразу в корне, чтобы
Railway не пришлось указывать Root Directory:

```
.
├── server/            (server.js, bot.js, db.js, auth-utils.js)
├── data/.gitkeep       (пустая — БД создастся сама при первом запуске)
├── css/ js/ *.html
├── package.json        (npm start -> start.sh)
├── start.sh             (запускает server.js + bot.js)
├── railway.json          (явный start command для Railway)
├── .gitignore
└── .env.example
```

## 1. Залить проект на GitHub

Railway проще всего деплоить из GitHub-репозитория (дальше каждый `git push`
будет автоматически передеплоивать сайт).

```bash
cd inside-client   # папка из этого архива
git init
git add .
git commit -m "Initial commit"
```

Создай пустой репозиторий на github.com (без README/лицензии), затем:

```bash
git remote add origin https://github.com/<твой-аккаунт>/inside-client.git
git branch -M main
git push -u origin main
```

Если не хочешь использовать GitHub — можно задеплоить и без него через
Railway CLI (`npm i -g @railway/cli`, затем `railway login` и `railway up`
прямо из папки проекта), шаги 2–5 ниже всё равно применимы.

## 2. Создать проект и сервис на Railway

1. Зайди на railway.app → **New Project**.
2. Выбери **Deploy from GitHub repo** → выбери репозиторий `inside-client`.
3. Railway определит Node.js-проект через Nixpacks и соберёт его
   автоматически (никаких доп. настроек сборки не нужно — зависимостей нет,
   стартовая команда уже прописана в `railway.json`).
4. Дождись, пока в логах деплоя не появится
   `Inside Client запущен: http://localhost:<PORT>`.

### Домен

Открой сервис → вкладка **Settings → Networking → Generate Domain**.
Именно это действие включает публичный доступ и заставляет Railway
подставлять переменную `PORT`, которую уже читает `server.js`.

## 3. Volume для базы данных (обязательно)

1. В сервисе: **Settings → Volumes → New Volume**.
2. Mount path укажи **`/app/data`**.
   - Nixpacks-сборки Railway кладут проект в `/app` внутри контейнера,
     поэтому `data/` из репозитория превращается в `/app/data`.
   - Если после деплоя увидишь в логах ошибку доступа к `data/...` или
     данные всё равно не сохраняются — открой **Deployments → View Logs**
     / вкладку **Shell** сервиса и проверь командой `pwd` и `ls`, какой
     путь реально используется, и поправь Mount Path на него.
3. Сохрани — Railway передеплоит сервис с примонтированным томом.

После этого файл `data/inside-client.sqlite` (и служебные `-wal`/`-shm`)
будут жить на Volume и переживут любые редеплои и рестарты. При самом
первом запуске `server/db.js` сам создаст файл, таблицы и три демо-ключа
активации (`DEMO-1111-2222-3333` и т.д.) — их стоит один раз использовать
или удалить из таблицы `activation_keys` перед реальным запуском в прод.

## 4. Variables

**Settings → Variables**. `PORT` трогать не нужно — Railway подставляет её
сама после генерации домена (шаг 2).

Если хочешь Telegram-привязку — добавь:

| Переменная              | Значение                                                                 |
|--------------------------|---------------------------------------------------------------------------|
| `TELEGRAM_BOT_TOKEN`     | токен, который выдаёт `@BotFather` при создании бота                     |
| `TELEGRAM_BOT_USERNAME`  | username бота без `@` (по умолчанию в коде `InsideClientBot`)            |
| `MODERATOR_USERNAMES`    | Telegram-username модераторов поддержки через запятую, без `@` (см. ниже) |

Если `TELEGRAM_BOT_TOKEN` не задан — сайт всё равно поднимется и будет
работать, просто кнопка «Привязать Telegram» и покупки (которые требуют
привязанный Telegram) будут недоступны, пока токен не появится.

### Тикеты поддержки в боте

Бот умеет вести тикеты поддержки: юзер жмёт «💬 Связаться с поддержкой»,
выбирает тему (оплата / клиент / сайт-аккаунт / другое) — заводится тикет,
дальше все его сообщения в чате автоматически попадают в этот тикет, пока
он открыт. Юзер может закрыть свой тикет сам кнопкой под сообщением.

Модераторы задаются переменной `MODERATOR_USERNAMES`, например:

```
MODERATOR_USERNAMES=ivan_support,anna_help
```

Username — без `@`, через запятую, регистр не важен. У аккаунтов из этого
списка в боте появляется кнопка «🎫 Тикеты» — список открытых/закрытых
тикетов, просмотр переписки, ответ и закрытие тикета. Ответить может любой
модератор из списка, отдельного назначения "своего" тикета нет.

Важно: бот узнаёт `chat_id` модератора автоматически, но только после того,
как тот сам хоть раз напишет боту (например, `/start`) — до этого момента
уведомления о новых тикетах ему приходить не будут. Поэтому после добавления
username в `MODERATOR_USERNAMES` попросите модератора один раз открыть бота
и отправить `/start`.

**Важно:** токен бота никогда не должен попадать в код или в git — только
через эту переменную. Если токен когда-то "засветился", перевыпусти его
командой `/revoke` у `@BotFather`.

После добавления переменных Railway сам передеплоит сервис.

## 5. Проверка

- Открой публичный домен сервиса — должен открыться `index.html`.
- Зарегистрируй тестовый аккаунт, зайди в личный кабинет — должны
  появиться UID, дата регистрации и т.д.
- Если задан `TELEGRAM_BOT_TOKEN`: в логах деплоя (Deployments → Logs)
  должна появиться строка вида `Бот запущен: @<username> (long polling)`.
- Сделай тестовый редеплой (например, пустой коммит `git commit --allow-empty`
  + `git push`) и убедись, что созданный ранее аккаунт никуда не делся —
  это подтверждает, что Volume примонтирован правильно.

## 6. На будущее / нюансы

- `node:sqlite` — экспериментальный модуль Node.js, в логах будет
  предупреждение `ExperimentalWarning: SQLite is an experimental feature` —
  это нормально, не ошибка.
- В `package.json` уже указано `"engines": {"node": ">=22.5.0"}` — этого
  обычно достаточно, чтобы Nixpacks выбрала Node 22. Если вдруг в логах
  сборки видно более старую версию Node — добавь переменную
  `NIXPACKS_NODE_VERSION=22` в Variables и передеплой.
- Бот держится простым бесконечным циклом long polling — если контейнер
  перезапустится, `restartPolicyType: ON_FAILURE` в `railway.json`
  перезапустит весь сервис (а вместе с ним и бота).
- Список того, что стоит доработать до полноценного прода (реальная
  оплата, HWID от лаунчера, rate-limiting и т.д.), уже описан в
  `README-backend.md` этого проекта — он не менялся.
